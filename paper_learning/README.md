# 论文复盘

在这个项目的对话里用自然语言开始。换新对话时，打开同一个论文库工作区即可接着用。

| 用户可以说 | 回复方式 |
|---|---|
| 开始复盘／论文库复盘总览 | 从 `knowledge_map.json` 读取带 `code` 的主体系和带 `parent` 的子类，给出总数、各 K 的名称及子类。用户已经点名时直接进入对应方向。 |
| 继续 K5／复盘决策计算／复盘 SuperMimic | 读对应历史的最近记录，简短交代上次覆盖了什么、哪里待续，从用户所选范围继续。初次复盘时，从该方向的问题结构和代表论文切入。单篇涉及多个方向时，沿用户当前讨论的体系记录，或在新对话里说明选用的子类。 |
| 查复盘历史／K5 有哪些卡点 | 按 K、论文或问题检索历史，只返回相关覆盖、已澄清的点和待续问题。查询本身无需新增记录。 |
| 今天先到这／把这个问题留到下次 | 补齐本轮记录，带一句已有进展和下次接续的问题。 |

选定 K 后，先给一屏结构和已有进度，再沿一个研究问题串两三篇。用户提出具体疑问时先直接解释，有需要就给足以区分机制的公式，注明变量、更新对象、梯度路径及原文位置。解释后把它接回当前体系。用户想练习时，每次只问一个主问题，再根据实际回复推进。单篇分析可从卡片和已有笔记开始，影响判断的细节回原文核对。

本地历史按 K 保存在 `history/k1.md` 至 `history/k7.md`，需要时再建文件。有实质进展就在回复前更新对应文件。同一轮的后续讨论补到原有条目，开始一轮新的复盘时追加条目。仅导航、查询或列出待复习论文时无需写入。记录专供这个工作区里的个人复盘，Git 忽略整个 `history/` 目录。

每条用日期和子类 ID 作标题，保留下面四项。用短句概括，必要时用论文名、稳定 ID 或章节定位，供下次按需读取。

- **实际讨论**写这次确实讲到的论文和主题。
- **澄清**写遇到的误解和得出的区别。已经讲解的内容与用户独立说清楚的内容分别表述。
- **待续**写一个具体问题或下一组比较。仅在总览里带过的论文留在这里。
- **依据**写足够找回关键公式或证据的链接与原文位置。
